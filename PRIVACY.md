# Calendar Hours privacy policy

Browser settings sync — October 27, 2026

Calendar Hours uses the browser provider's built-in sync service for preferences when browser sync is enabled. Chrome and Edge have separate sync services. Formatting, matching phrases, feature switches, and Workday calendar selections/import preferences can sync between installations with the same extension ID under the same browser account. OAuth tokens remain in local extension storage and are not included. The automatically detected device/Calendar time zone remains in tab memory; the explicitly chosen Workday payroll zone is a synced preference. No Firebase service or new account is used. Saving a preference does not confirm delivery to another device; your browser controls that delivery.

Workday import — October 27, 2026

The optional Workday integration adds access to `https://www.myworkday.com/*`. When you select Auto-fill from Calendar, it reads the displayed Enter Time dates and existing time blocks, requests the selected Google calendars’ events for those dates, and matches event titles to import start/end times. It saves these entries as unsubmitted through the visible form. An optional setting also updates one overlapping, unsubmitted draft in place when it corresponds to one calendar block. New comments are blank by default, and existing comments are preserved during time updates. If you enable Import event descriptions as comments, Calendar descriptions are sent to your Workday organization as plain-text comments (up to 1,000 characters), replacing comments on updated entries. Event titles are never copied to comments. Calendar data is sent to your Workday organization only when you start an import; the developer receives none of it.

General settings now manage one Google Calendar connection for title updates and Workday import. One authorization request asks for event view/edit access and read-only calendar-list access to show your available calendars. Existing connections with both permissions continue to work; event-only connections need an explicit upgrade. Connecting or disconnecting preserves feature preferences, and disconnecting removes access for all features. The selected calendar IDs/names, matching phrase, time zone, time type, out reason, and import preferences are stored in browser sync storage. Import results and event data are not persisted in extension storage. The existing short-lived Google token remains restricted to trusted extension contexts. Workday credentials and cookies are not read or stored by the extension. It does not use a developer server or private Workday API.

General feature policy — effective October 27, 2026

Calendar Hours reads the title, start time, end time, and date fields of a Google Calendar event on the open Calendar page. It uses those fields locally in your browser to calculate an elapsed duration and propose or insert hours or minutes in the event title. When Dynamic is enabled for a matching phrase or the existing-duration update setting is on, it detects when you move or resize a qualifying one-time event on the Calendar grid and displays the new duration immediately. By default, it opens that event in an inactive Calendar tab, corrects its title, and uses Google Calendar's own Save button. The existing-duration update setting starts on for new installations and can be turned off in Settings.

Time zone calculations read Calendar’s primary time zone and zone-label data already loaded on the Calendar page, plus event-specific zone labels. If unavailable, the extension reads the browser’s current system time zone. This happens locally, needs no location permission or additional Google scope, and does not change your Calendar or device settings. Zone detection data is kept in memory for the tab, not persisted or sent to the developer.

An optional faster-save mode connects to Google Calendar through Google's OAuth and Calendar API. Google grants access to view and edit events on your calendars. For a qualifying one-time grid change, the extension requests the specific event from Google's Calendar API, checks its title and times, and sends a request that changes only the title. It stores a short-lived OAuth access token in the browser's local extension storage and restricts that storage to trusted extension contexts where supported. When the token expires, it tries to renew access through Google's browser sign-in without showing a window; if Google requires interaction, the direct save falls back to the inactive Calendar tab until you reconnect. Disconnecting asks Google to revoke the token and removes the locally stored copy.

Calendar Hours does not collect, sell, or share calendar event data with its developer or services other than Google Calendar for the user's requested title save and the user's Workday organization for a requested time import. It has no analytics, advertising, account system, or developer-operated server. Your formatting and trigger preferences are stored using the browser's sync storage. If browser sync is enabled, the browser provider may sync these preferences under your browser account. Earlier versions stored small suggestion-instruction counts without event details; version 0.2.12 no longer reads or updates those counts. Optional OAuth tokens are stored locally, separately. No event titles or event times are stored in extension storage.

The extension requests access to `calendar.google.com/calendar/*` because that is where the event editor appears. It requests `storage` for preferences and optional local tokens, `identity` for the optional Google sign-in, and access to Google's Calendar and OAuth endpoints for the optional direct save. You can disconnect the Google account in settings or remove the extension and its stored data in your browser's Extensions settings.

For questions about this policy, use the support contact listed on the Chrome Web Store listing.
